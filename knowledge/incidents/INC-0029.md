## Root cause
The get_db() function in app/api/payments.py closes the database session in its finally block without first rolling back any uncommitted transaction. When an exception occurs during request processing, the corrupted connection is returned to the pool, causing subsequent requests to fail with OperationalError.

## Causal chain
- Request to GET /customers/{id}/payments encounters an error
- Exception occurs during request processing
- finally block in get_db() calls db.close() without db.rollback()
- Uncommitted transaction remains active on closed session
- Corrupted connection returned to connection pool
- Subsequent requests retrieve corrupted connection and fail with OperationalError

## Recommended action
Modify the get_db() function in app/api/payments.py to call db.rollback() before db.close() in the finally block (around line 32). This ensures that any uncommitted transactions are rolled back before the connection is returned to the pool, preventing corrupted connections from being reused by subsequent requests.
