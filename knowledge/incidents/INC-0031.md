## Root cause
The fraud-mock dependency service is taking approximately 5.0 seconds to respond (E2), which meets or exceeds the 5-second HTTP timeout configured in the payment-service's httpx client (E5). This causes ReadTimeout exceptions that propagate unhandled to the caller (E7), resulting in 500 errors.

## Causal chain
- Payment request arrives at POST /payments
- create_payment calls fraud-mock service via httpx.post with 5s timeout
- fraud-mock service latency is ~5014.97ms (E2: 99.6% of total span time)
- HTTP timeout fires before fraud-mock responds
- ReadTimeout exception is not caught (E7)
- Exception propagates unhandled, logged as incident

## Recommended action
Increase the httpx timeout in app/api/payments.py:create_payment from 5 seconds to at least 6 seconds, or investigate why fraud-mock is operating near its timeout threshold. Alternatively, implement retry logic with exponential backoff or circuit breaker pattern to gracefully handle timeouts from the fraud-mock dependency. Additionally, add explicit exception handling for httpx.ReadTimeout to provide better error messages and implement fallback behavior.
