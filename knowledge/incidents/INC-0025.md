# INC-0025: unclosed engine.connect() in a module-level list exhausts the pool

**Service:** payment-service
**Category:** DATABASE
**Exception:** TimeoutError
**Confidence:** 0.3 (low)

## Root cause
Commit 1dc0c6ec introduced a duplicate-payment probe that obtains database connections via engine.connect() and stores them indefinitely in a module-level _recent_probes list without ever closing them. This causes connection pool exhaustion (5+5=10 max connections), triggering TimeoutError on subsequent requests when the pool is saturated.

## Causal chain
- POST /payments requests execute duplicate-payment probe logic added in commit 1dc0c6ec
- Each request obtains a database connection and appends it to module-level _recent_probes list without closing
- Connections are never returned to the pool and references persist indefinitely
- With pool_size=5 and max_overflow=5 (10 total), all slots exhaust after ~10 sustained requests
- Subsequent requests timeout waiting for an available connection
- TimeoutError raised and logged as unhandled exception

## Recommended action
Revert commit 1dc0c6ec ('Add duplicate-payment probe before fraud check'). If the duplicate-payment check is required, reimplement it with proper connection lifecycle management: use context managers (with engine.connect() as conn:) to ensure connections are returned to the pool, or use a connection pooling strategy that bounds the _recent_probes list (e.g., maxlen deque or LRU cache).
